# Unia BiliBili Bot

基于 Node.js 的 Bilibili 动态与直播监控机器人，适配 NapCat (OneBot 11)。

## 功能
- 监控指定用户的 Bilibili 动态（支持图文、视频投稿），并推送到 QQ 群。
- 以高分辨率无损 PNG 卡片推送动态；多目标和自定义消息模板复用同一份渲染结果，避免重复截图。
- 监控指定用户的直播间状态（开播、下播），并推送到 QQ 群。
- 提供 Web 前端界面进行配置和扫码登录。

## 安装

1. 进入目录：
   ```bash
   cd unia-bot
   ```

2. 安装依赖：
   ```bash
   npm install
   ```

## 运行

1. 启动服务：
   ```bash
   npm start
   ```

2. 打开浏览器访问：
   http://localhost:3001

3. 在网页中：
   - 点击“获取登录二维码”并扫码登录 Bilibili。
   - 配置 NapCat 的 HTTP API 地址（例如 `http://127.0.0.1:3000`）。
   - **注意**：本机器人运行在 3001 端口。

4. 添加监控用户：
   - 输入用户的 UID (MID)。
   - 输入需要推送的 QQ 群号。
   - 点击添加。

## 动态卡片渲染性能

动态卡片使用 `deviceScaleFactor: 2` 与高质量 WebP 截图，并限制超长图片和卡片高度，避免大图导致 Chromium 内存暴涨。

- 每条动态在单次处理过程中只渲染一次；所有群聊、私聊及其自定义动态模板复用同一张图片。
- 动态卡片严格单并发渲染；渲染超过 90 秒时会主动关闭页面并降级到原图，避免超时任务继续占用资源。
- 截图前会等待字体、`<img>`、CSS 背景图和浏览器绘制完成，而不是等待网络完全空闲；这能避免慢图片请求将卡片渲染不必要地拖慢。
- 控制台会输出 `[Card render performance]` 阶段耗时；事件日志会记录 `dynamic_performance`，其中 `cardRenderCount: 1` 表示该动态没有被重复渲染。
- 普通资源错误只影响当前页面；只有 Chromium/DevTools 连接级错误才会重启浏览器实例。
- NapCat 发送会等待 OneBot 响应确认；部分目标失败时只重试失败目标，成功记录会保存到配置文件中。

### 过载与投递保护

- Chromium 同一时间只处理一张动态卡片，避免突发动态同时创建多个高分辨率页面。
- 单张卡片渲染最长等待 90 秒；超时后关闭对应页面，并在存在动态原图时自动使用原图发送。
- NapCat 消息按队列顺序发送，间隔 750 毫秒；WebSocket 和 HTTP 请求最长等待 15 秒。
- 每个群聊或私聊目标独立确认投递结果。已经成功的目标会立即保存，其他目标失败时采用指数退避重试，最长间隔 10 分钟。
- 动态只有在所有启用的目标均投递成功后才会更新 `lastDynamicId`，不会再因为部分目标成功而跳过其余失败目标。

## 目录结构
- `src/bili-api.js`: Bilibili API 封装 (含 WBI 签名)。
- `src/bot.js`: 监控逻辑与消息推送。
- `src/config.js`: 配置管理。
- `src/napcat.js`: NapCat 接口封装。
- `src/server.js`: Web 服务器。
- `public/`: 前端静态文件。
